# 2026-09-16

### 修复

- 修复 Responses API 请求在唯一渠道 429 后 failover 到 `responsesMode=disabled` 渠道时返回裸 `501 Not Implemented`(无响应体,客户端显示 "Unknown error")的问题:`try_add_fallbacks` 收集 fallback 候选时排除不支持 Responses 端点(native/chat_compat 之外)的渠道,让冷却/失败的初始渠道把真实错误透传给客户端(`rust-proxy/src/proxy.rs`)。
- 初始路由本身不支持 Responses API 时的 501 响应补充 JSON 错误体(`responses_not_supported`)与终端响应日志,不再返回无 body 的裸状态码。
- 修复 chat_compat SSE 转换器重复发送 `response.completed` 终结事件的问题(`rust-proxy/src/responses.rs`):此前每个带 `finish_reason` 的 chunk 都会触发一次 completed,流结束的 `finish()` 兜底还会再补一个 —— 中转上游(kiro/astream 等)在流尾重复下发 finish chunk 时,客户端(codex)在第一个 completed 后按协议正常关闭连接,却被记为 499。新增 `completed_sent` 状态保证全流只发一次;上游异常截断(从未出现 finish_reason)时兜底补发逻辑保留。TS 侧转换器本就有 `finalized` 守卫,无此问题。
- 修复 chat_compat 转换的 `usage` 未映射为 Responses 规范字段的问题(`rust-proxy/src/responses.rs`):completed 事件(流式)与响应对象(非流式)此前直接透传 chat 格式(`prompt_tokens`/`completion_tokens`),codex 等客户端强类型解析 `ResponseCompleted` 时报 `missing field input_tokens` 断流重连。新增 `convert_chat_usage_to_responses_usage`(对齐 TS `convertChatUsageToResponsesUsage`):`prompt_tokens→input_tokens`、`completion_tokens→output_tokens` 并映射两组 details;上游缺失 usage 或兜底补发时输出字段齐全的全 0 对象。

### 变更

- 全部候选渠道都处于 429 冷却时,忽略最后一个渠道的冷却状态直接放行请求(`bypassing cooldown as last resort`):仍被限流则透传上游真实 429 与 Retry-After,已恢复则成功并自动解除冷却;不再返回网关自造的冷却 429 响应(删除 `build_rate_limit_cooldown_response`)。冷却跳过仅在实际存在可用 fallback 时生效。
- failover 链路最终失败时回传链上最后一个真实收到的上游 HTTP 错误响应(新增 `CachedUpstreamError` 快照,丢弃响应去重试/回退前缓存状态码、响应头与错误体):后续渠道仅出网络错误、首字节超时、熔断跳过或路由耗尽时,客户端拿到的是真实上游错误而非网关自造的 502/503/504。

### 测试

- `rust-proxy` 新增单测:Responses 请求的 fallback 排除 disabled 渠道、非 Responses 请求不受影响、全部候选不可用(disabled + 冷却)时不再添加 fallback;chat_compat SSE 转换在重复 finish chunk + 流结束兜底下只产生一个 `response.completed`、异常截断时兜底补发仍生效。

### 修复(2026-09-16 晚间追加)

- 修复 chat_compat SSE 转换器正文全部丢失的问题(`rust-proxy/src/responses.rs`):`text_started` 只在 `flush_text_to_output` 尾部置位、而 flush 又仅在 `text_started==true` 时执行,形成死锁 —— 正文永远不 flush,客户端只收到 created+completed 的空响应(codex 表现为"不可用")。现在收到非空 `delta.content` 即置位。
- `response.completed` 事件补 `output` 数组(新增 `build_output_items`:reasoning/message/function_call 汇总,文本跨 flush 全量累积),codex 等客户端以 completed.output 为最终内容依据。
- 文本与 tool_calls 交错时 message item 的 `output_item.added`/`content_part.added` 只发一次(新增 `message_started` 标志),function_call items 按 call_id 去重后进入 completed.output。
- `finish()` 兜底:异常截断的残留文本先作为最后一段 delta 发出并计入 completed.output,再补终结事件(此前该路径提前 return,客户端收不到 completed)。
