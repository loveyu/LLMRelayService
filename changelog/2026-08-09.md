# 2026-08-09

### 新增

- **日志页支持按 id 分享/定位**：`/#/logs` 点击某条日志后，把选中的 `request_id` 写进 URL（`#/logs?id=<id>`），刷新/复制链接即可回到同一条；关闭抽屉自动清掉 `?id=`。便于排查时把具体日志 id 直接发出去或对照后端日志。
  - 实现方式：`selectedId` 保持本地 state（关闭抽屉只重渲染 LogsPage，不重渲染 App、不动列表），URL 的 `?id=` 用 `history.replaceState` 静默同步（不触发 hashchange）；`LogsPage` 初值从 `?id=` 读取，直接打开链接即定位。
- **详情头补充复制 request_id 按钮**：详情抽屉顶部新增一行始终可见（含移动端）的 `request_id`（带 `title` 全文 + `truncate`）+ 复制按钮（移动端仅图标、桌面端带文案），点击走 `copyText` + toast；替代原先仅桌面端可见的截断 id，移动端也能直接看/复制日志 id。
- **payload 原始模式引入 CodeMirror**：`PayloadPanel` 的「原始」模式用 CodeMirror 6 替换只读 Textarea，支持 JSON 语法高亮、行号、括号匹配、对象/数组折叠（gutter 点击或快捷键），并跟随应用深色/浅色主题（`oneDark` / `light`）。
  - 实现方式：新增 `components/ui/json-code-viewer.tsx`（封装 `@uiw/react-codemirror` + `@codemirror/lang-json` + `@codemirror/theme-one-dark`，只读、关闭自动补全）+ `hooks/use-is-dark-mode.ts`（监听 `documentElement` 的 `.dark` class）。
- **原始模式操作栏（blob + 复制）**：原始模式编辑器（语法高亮）上方新增两个按钮——「新窗口打开」把格式化 JSON 写成 `blob:` 链接并在新标签页打开（全屏查看，`window.open` 被拦截时 toast 提示）；「复制原始」复制未格式化的原始 payload（直接取 prop，不经 2-space 重排）。

### 变更

- **日志页移动端改用卡片列表**：`/#/logs` 在窄屏（`< lg` / 1024px，与详情抽屉、每页条数一致）下不再渲染多列表格，改为逐条堆叠的可点击卡片。每张卡片包含 状态码徽标、时间、路由(渠道)+测试标记、模型 · 来源，以及一行 4 格指标条（入/出 Token、缓存命中率、首 Token 延迟、价格），加载态用卡片骨架、空态沿用原 Empty。
  - 实现方式：`RequestLogTable` 新增 `isMobile` prop（由 `LogsPage` 透传已有的 `useIsMobile`），compact 变体在 `isMobile` 时渲染新增的 `RequestLogMobileCard` + `StatCell`，桌面端（≥ lg）保持原 7 列 grid 表格不变；复用既有 `statusStyle` / `calculateRequestCacheHitRate` / 格式化工具，无新 i18n key。

- **请求详情抽屉移动端优化**：`/#/logs` 点开的详情抽屉在窄屏（`< lg`）下做了一组适配。
  - 全部一起滚动：移动端把 顶部状态/指标头 + Tabs + 面板内容 + 底部条 收进同一个 `ScrollArea`，整页一起滚，不再让 8 格指标头常驻占掉一大块视口；桌面端仍保留 头部/Tabs/底部条 固定、仅面板滚动的原布局。
  - 顶部头修复：状态徽标 / 路由加 `shrink-0`，模型名加 `min-w-0`，长模型名+渠道在窄屏可靠截断不互相挤压。
  - 请求概况卡片：`grid-cols-2` → `grid-cols-1 sm:grid-cols-2`，`request_id` / `target_url` / `path` 等长 mono 值在移动端独占整行可读，不再被压成半行。
  - 底部条：`px-6` → `px-3 sm:px-6`；冗长 hint 在移动端隐藏（`hidden sm:inline`）；「复制」按钮加大点击区（`px-2 py-1.5` + hover bg）。
  - 实现方式：`DetailView` 引入 `useIsMobile`，把 header / tabsList / tabPanels / bottomBar 抽成共享块，按 `isMobile` 在「单滚动」与「桌面固定」两种结构间分支，避免内容重复。
  - 数据来源：抽屉与独立详情页（`detail-page`）共用 `DetailView`，两处同步生效。

### 修复

- **日志页关闭抽屉后列表空白、需刷新**：上一版把 `selectedId` 改成由 hash query param（`#/logs?id=`）驱动，点选/关闭都走 `navigate` 改 `location.hash`，触发 `hashchange` → 整个 App re-render，关闭抽屉后日志列表需要刷新才回来。改回 **本地 state** 持有 `selectedId`（关闭只重渲染 LogsPage，不动列表），URL 里的 `?id=` 改用 `history.replaceState` 静默写入（不触发 hashchange、不重渲染 App）；初值仍从 `?id=` 读取，直接打开/分享 `#/logs?id=<id>` 仍能定位到该条。同步回退 `use-hash-route` / `App` 里为 id 加的路由字段。

- **连通性测试日志没有响应头**：日志页详情「响应头」对 `source_request_type=connectivity_test` 的记录一直显示「没有响应头」。根因是 `rust-proxy/src/provider_test.rs` 的连通性探测拿到上游响应后只取了 `status` / body，丢弃了 `resp.headers()`，写响应日志时硬编码 `response_headers: json!({})`（DB 核对：15 条空响应头记录全是 connectivity_test，真实转发记录都有数据）。修复：`TestOutcome` 新增 `response_headers` 字段，`handle_upstream_response` / `handle_stream_response` 在消费响应体前用新增的 `header_map_to_json(resp.headers())` 快照上游响应头（结构对齐真实转发路径 proxy.rs），`emit_response_log` 改用该快照；连接失败/超时无上游响应时仍为空对象。

- **CodeMirror 在 dev 下报 Invalid hook call**：引入 `@uiw/react-codemirror` 后，dev server（vite）把它按源码 ESM 单独解析，`react` 解析到与 app/react-dom 不同的实例，触发 `Cannot read properties of null (reading 'useRef')`。`vite.config.ts` 加 `optimizeDeps.include: ['@uiw/react-codemirror']`（预打包，复用同一份 optimized react）+ `resolve.dedupe: ['react','react-dom']`（强制 react 单例）；改后 react-dom / app / @uiw 共用同一份 `react@19.2.8` chunk。生产构建不受影响（rollup 天然去重）。

- **详情指标标签显示为 i18n key**：`detail.inputTokens` / `detail.outputTokens` 两个 key 此前在 zh/en locale 都缺失，导致详情头部的 4×2 指标格里直接显示 `detail.inputTokens` 字面量。补齐为「输入 tokens / 输出 tokens」「Input Tokens / Output Tokens」。
