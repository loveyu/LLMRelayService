# 2026-08-07

### 新增

- **Rust 代理引擎** (`rust-proxy/`)：用 Rust 重写核心转发流程，替代 TS 的代理职责
  - Axum HTTP server + reqwest upstream 转发
  - 路由匹配：显式路由 `/providers/{channel}/...` + 模型名匹配 + 别名解析
  - 认证：Gateway admin key + SHA-256 managed API key 本地查找
  - Body 变换：Anthropic system prompt 注入、claudeCodeCompat、响应 model 名重写
  - URL 构造对齐 TS：OpenAI 类型自动去 `/v1` 前缀 (`path.slice(3)`)
  - 故障转移：同路由重试 + same_model/any_model fallback（仅 retryable 状态码触发）
  - 流式 SSE 代理 + ModelRewriter 字节流实时替换
  - 独立端口（默认 3301），`RUST_PROXY_HOST`/`RUST_PROXY_PORT` 可配
- **TS 管理 Rust 进程** (`src/rust-process.ts`)：TS 启动时 spawn Rust 子进程，自动重启（崩溃后最多 5 次，3s 间隔），每 15s HTTP 健康检查，SIGTERM 转发
- **IPC 双向通信**：Unix Domain Socket 长度前缀帧协议，TS ↔ Rust 配置同步 + 日志回写
  - TS 启动/配置变更时推送 `SyncConfig`（providers + aliases + failover + timeouts + api_keys）
  - Rust 发送 `RequestLog`/`ResponseLog`，TS 写入 `console_requests` 表（`src/rust-log-writer.ts`）
- **配置热更新**：Console UI / OpenAPI 的 16 个变更路径（provider/alias CRUD × 2 API 入口）均调用 `syncConfigToRust()` 实时推送
- **Console API**：`GET /__console/api/rust-proxy/status` + `POST .../restart`
- **Docker 构建**：三阶段 Dockerfile（bun builder → rust:alpine builder → oven/bun runner），入口简化为 `bun run src/server.ts`
- **性能对比工具** (`test_compare.py` / `bench_proxy.py`)：TS vs Rust vs 直连三方对比

### 修复

- URL 构造：OpenAI 类型 provider 的 base URL 含 `/v1` 前缀时，正确去除请求路径中的 `/v1` 避免双 `/v1/v1`
- Alias 解析：UUID 到 provider 查找、`resolved_model` 设置、请求 body 中 model 名重写
- 流式响应 model 名重写：修复 `ModelRewriter` callback 重复拼接 capture groups 的 bug
- IPC 广播：新客户端连接时不再关闭旧连接（`Vec<active_writers>` 替代 `Option`）
- 日志写入：补全 `failover_chain`/`original_summary` 等 `saveConsoleRequest` 必填字段
- 渠道编辑页移动端适配：点击渠道时从底部弹出 `Sheet` 抽屉编辑，抽屉内部可滚动，桌面端保持分栏布局不变
- Rust 代理监控页面：新增 `rust-proxy-page.tsx`，展示进程运行状态、PID、运行时间、重启次数、健康检查结果、监听地址等，支持手动重启，5 秒自动刷新。顶部导航栏右侧新增 Cpu 图标入口（`#/system`）
- Rust 代理状态 API：`getStatus()` 新增 `realpath` 字段（`fs.realpathSync` 解析），前端以全宽 `break-all` 展示文件路径，并在 realpath 与 bin 不一致时额外显示 bin 简名
- IPC accept loop 自动恢复：Rust 侧 `catch_unwind` 包裹 accept 循环，panic 后 1s 自动重启；TS 侧 bridge 在断连 >30s 后自动调用 `restartRustProxy()` 重启 Rust 进程
- **TS→Rust 功能补全**（关键缺失）：
  - **每 Key 模型白名单**：`auth.rs` 新增 `is_model_allowed()`，`proxy.rs` 认证后校验 `allowed_models`，网关管理员 key 不受限制
  - **OpenAI Responses API 兼容**：新增 `responses.rs` 模块（800+ 行），支持 `chat_compat` 模式（Request 请求转换、URL 重写、SSE 事件转换、非流式响应转换），`native`/`disabled` 模式
  - **CORS**：添加 `CorsLayer::permissive()`，支持 `*` 来源和所有方法/头
  - **Custom model fallback**：`try_add_fallbacks()` 集成 `get_custom_model_fallbacks()`，支持 per-model 自定义故障转移链
  - **`/v1/models` 端点**：返回 provider 模型 + alias 合集，支持 `/openai/v1/models`、`/anthropic/v1/models`
  - **`maxFallbackAttempts`**：在 `try_add_fallbacks()` 中强制执行，fallback 候选去重后按最多 `maxFallbackAttempts` 条添加
  - **`/v1/messages` 作为 Anthropic**：`routing.rs` 中 `infer_expected_provider_type` 优先将 `/v1/messages` 判为 Anthropic
- **Token usage 捕获**：非 SSE 响应完整读取 body 后从 JSON 解析 `usage`（prompt/completion/total_tokens），非流式响应同时记录 `response_body_bytes`；SSE 流式保持原有 None
- **Response body idle timeout**：改为依赖 reqwest 内置 `read_timeout` 覆盖闲置超时场景（Axum streaming 层手动实现 idle timeout 开销过大）
- **前端构建**：`bun run build` 通过，后端 `cargo build` 通过
- **IPC 日志回写竞态条件**：`server.ts` 中 request_log/response_log handler 使用动态 import 并发执行，导致 saveConsoleResponse 的 UPDATE 在 saveConsoleRequest 的 INSERT 完成前执行（匹配 0 行），response 数据丢失。改为串行队列保证先 INSERT 后 UPDATE
- **saveConsoleResponse 参数结构不匹配**：handler 将 timing 字段作为顶层字段传入，但 saveConsoleResponse 期望 timing 嵌套在 response_timing 子对象中；补全 response_payload/response_payload_truncated/response_usage 必填字段
- **Rust proxy RequestLog 缺少 API key 信息**：send_request_log 硬编码 api_key_id/api_key_name 为 None，现在从 auth_result 提取并传递
- **Rust proxy ResponseLog 缺少首字节时间**：first_chunk_at 硬编码 None，现在用请求时间 + t_ttfb 计算绝对时间戳写入
- **优雅关闭**：server.ts 新增连接排空（bunServer.stop + pendingRequests 轮询，最多等待 15s），docker-compose 新增 stop_grace_period: 15s
- **Rust proxy RequestLog 原始请求体丢失**：send_request_log 始终传 original_payload=None，现在传入原始 body（未变换的请求内容）
- **Rust proxy ResponseLog 缺少缓存 token**：新增 cache_creation_input_tokens/cache_read_input_tokens/cached_input_tokens 提取，IPC 消息和 TS 映射同步扩展
- **Rust proxy SSE 流式请求缺少 token 数据**：新增 `sse_observer.rs`（ObservingSseStream + PassthroughObserver），在 SSE 流式响应中并行缓冲（4MB/300s 限制），流结束后解析 Anthropic SSE 事件提取 token 用量和 stop_reason，通过补充 ResponseLog 写回 DB。`extract_usage_values` 支持覆盖 message_start 中的零值（真实值在 message_delta 中）
- **Rust proxy ResponseLog 缺少响应 body**：ResponseWithUsage 新增 body_content 字段，非流式响应传递完整 body 内容，IPC 消息和 TS 映射同步扩展
- **ModelRewriteStream UTF-8 字节边界 panic**：`flush_end` 计算（`buffer.len() - safe_tail`）可能落在多字节 UTF-8 字符中间（如 3 字节中文字符），导致 `buffer[..flush_end]` 切片 panic，TCP 连接断开，客户端收到 HTTP 200 + closed。修复：(1) 使用 `floor_char_boundary()` 将 flush 切割点对齐到最近的合法字符边界；(2) `catch_unwind` 包裹整个 `poll_next` 循环体，panic 时转为 `axum::Error` 流错误而非崩掉 tokio task
