### 新增

- **模型页（`#/models`）移动端改造为卡片列表**：原模型表格有 8 列（模型 ID / 上下文 / 4 种价格 / 渠道 / 操作），移动端只能横向滚动、难以阅读。用 `useIsMobile()`（`<lg` 断点，与渠道/日志页一致）分流：桌面端保留原 `<Table>`（抽为 `ModelDesktopTable`），移动端渲染 `ModelMobileList`——每个模型一张卡片，顶部为模型 ID（`font-mono` + `break-all`）+ 渠道 Badge，下方先整行列「上下文长度」，再用 `grid-cols-2` 网格列出 4 项价格（`tabular-nums`），手动改写过的字段仍显示「手动」Badge，底部为两个 `flex-1` 铺满宽度的「测试 / 编辑」按钮（图标+文字）。空数据态在两条分支前统一处理。
- **模型连通性测试支持复制结果**：测试弹窗底部新增「复制结果」按钮（仅在已有测试结果时显示），点击将结构化摘要写入剪贴板并用 toast 反馈（复用 `common.copied` / `common.copyFailed`）。摘要包含 渠道 / 模型 / 协议(openai|anthropic) / 状态(含 HTTP 码) / 延迟 / 消息，并从原始响应 `usage` 抽取「输入 / 输出 tokens」（同时兼容 OpenAI 的 `prompt_tokens/completion_tokens` 与 Anthropic 的 `input_tokens/output_tokens`），末尾追加完整原始响应 JSON，便于把测试结果贴出去排查失败原因。
- **连通性测试记录到日志页（与真实转发同构）**：模型页 / 渠道页 / 路由页「测试」按钮触发的连通性探测（Rust `POST /admin/providers/{channel}/test`）此前不留任何日志，排查失败只能看弹窗一次性结果。现在测试过程与真实转发走同一条日志链路：`rust-proxy/src/provider_test.rs` 测试时生成 `request_id`，经 IPC 发 `RequestLog`（探测前，记录渠道/模型/上游地址/探测请求体）和 `ResponseLog`（探测后，记录上游状态码/响应体/耗时/用量），字段与 `proxy.rs::send_request_log` 对齐；所有结局（成功 / 非流式与流式 / 上游错误 / 连接失败 / 超时）都写日志。IPC `RustToTsMessage::RequestLog` 新增 `sourceRequestType` 字段——真实转发传 `chat_completion`（行为不变），连通性测试传 `connectivity_test`；`src/server.ts` 的 IPC handler 把它写入 `console_requests.source_request_type`，`rust-log-writer.ts`（standalone 备用路径）同步读取。
  - 测试日志在日志页正常可见，`client_label` 标为「连通性测试」，`request-log-table.tsx` 两个变体（compact / default）都在渠道旁加「测试」Badge（`logTable.testBadge`，中/英 i18n）。
  - **不污染用量大盘**：测试是合成探测（固定 prompt「Reply with exactly OK」），不应计入用量/成本/健康度。`console-store.ts` 的 `listUsageRows`（驱动物料/网关/用量三处统计）与 `getProviderHealthStatuses` 都加 `source_request_type IS NULL OR <> 'connectivity_test'` 过滤；日志列表 `listConsoleRequests` 不过滤（保留用于排查）。
  - 实测：对 `deepseek` 渠道探测命中上游 401（凭证失效），日志页可见一条 `source_request_type=connectivity_test` 记录，含 `response_status=401`、响应体、`completed_at` 时间戳；用量统计的「有响应行」计数 120 → 过滤后 119（恰好排除该测试行），大盘不受影响。

### 修复

- **强制流式上游的渠道连通性测试失败（如 `zzc-o / gpt-5.6-sol` 报 `HTTP 400: {"detail":"Stream must be set to true"}`）**：连通性测试构造的探测请求体不带 `stream`（沿用旧 TS 实现），而部分上游（推理类模型 / 内部中转）强制要求流式，直接返回 400。`rust-proxy/src/provider_test.rs` 改为「自动检测 + 流式重试」：默认仍非流式（行为不变），仅当上游错误文本明确表示「必须流式」（匹配 `stream` + `must`/`set to true`/`requir`/`needs to` 等）时，自动带 `stream:true` 重试并解析 SSE（OpenAI 聚合 `choices[].delta.content/reasoning_content` + 末尾 chunk 的 `usage`；Anthropic 按 event 聚合 `text_delta/thinking_delta`、`message_start`/`message_delta` 合并 `usage`），再按非流式结构合成 `rawResponse` 复用既有成功判定（含 OK / 思考模型 / 截断），前端 `TestProviderResult` 与用量展示无需改动。
  - **首次探测后内存记忆，避免重复付失败的非流式往返**：`AppState` 新增 `test_requires_stream: Arc<RwLock<HashSet<String>>>`（key = `"{channel}\u{0}{model}"`）。首次探测到某 `(channel,model)` 上游强制流���后写入记忆，后续对该组合的测试直接走流式、跳过注定失败的非流式尝试。记忆纯内存级，rust 进程重启失效（重启后首个请求重新学习一次）。
  - 实测：dev 库 4 个 OpenAI 渠道里仅 `zzc-o/gpt-5.6-sol` 强制流式（bigmodel/deepseek/opencode-o 均接受非流式），自动检测只对该渠道触发、对其余渠道零影响；流式重试对该模型返回 `delta.content:"OK"` + `usage{prompt_tokens:2499,completion_tokens:5}` 正常。经 restart 端点用新二进制重拉 rust-proxy 后，同一模型连测 3 次：第 1 次（记忆未命中）wall=3.2s（含 ~1s 失败的非流式 + 流式重试 + 写记忆）、第 2/3 次（命中记忆）wall≈1.8~2.3s（直接流式），差异即被跳过的失败往返；三次均 `status:ok`（旧二进制为 `error 400 Stream must be set to true`）。
  - 注：正常代理转发路径不受影响——客户端 `stream:true` 经 `proxy_handler` 对 OpenAI 类路由原样透传（仅改写 `model` 字段，不触碰 `stream`），上游正常返回 SSE。本次改动只在连通性测试路径加记忆，转发路径未动。

- **内网 HTTP 部署下「复制」全部失败（如 `http://10.4.125.53:5180` 复制测试结果报「复制失败，请手动复制」）**：根因是 `navigator.clipboard.writeText` 仅在安全上下文（HTTPS / localhost）可用，内网 HTTP + 非 localhost 时 `navigator.clipboard` 为 `undefined`，调用直接抛错。抽取公共复制方法 `src/lib/clipboard.ts` 的 `copyText`：优先用 Clipboard API，不可用或失败时回退到「临时 `<textarea>` + `select()` + `document.execCommand('copy')`」（不依赖安全上下文）。模型测试结果、API Key、导出配置、API 文档示例、请求详情五处复制统一改用它；并删除 `features/dashboard/utils.ts` 里无人引用的同名旧 `copyText`。
  - 在本机 `http://10.4.125.53:8300`（非安全上下文）实测：`navigator.clipboard` 确为 `undefined`，点击「复制结果」会走 `execCommand('copy')` 兜底（返回 true，不再报失败）。

- **复制「提示成功但内容为空」**：上一条的 `execCommand` 兜底用「`<textarea>.focus()` + `select()`」方案，在 Radix Dialog 焦点陷阱里失效——陷阱会把焦点抢回 Dialog，textarea 失焦后 `execCommand('copy')` 虽返回 true，实际复制内容为空。`src/lib/clipboard.ts` 的兜底改用：离屏 `<span>` + `Range` 选中（**不依赖焦点**，绕开焦点陷阱）+ 监听一次 `copy` 事件用 `clipboardData.setData('text/plain', value)` 显式写入内容（`white-space: pre` 保留换行），并恢复用户原选区。
  - 焦点陷阱下实测对比：旧方案 `execCommand` 返回 true 但 textarea 已失焦（复制为空）；新方案 `copy` 事件 `setData` 写入完整内容。在本机 `http://10.4.125.53:8300` 测试弹窗（焦点陷阱 + 非安全上下文）实测 `setData` 写入 432 字符完整摘要（渠道/模型/协议/状态/延迟/消息 + 原始响应 JSON）。

- **渠道编辑页无法添加模型（关键 bug）**：编辑面板（`renderEditPane`）里"添加模型"输入框的回车处理调用的是 `addModelRow()`，而该函数只 push 一个空 `createModelRow()`，输入框里的模型名被直接丢弃、清空，所以编辑渠道时输入模型名回车后什么都不出现。`+` 按钮也绑定同一个空行函数，同样无效。新建弹窗虽然回车能正确写入，但没有提交按钮，移动端只能依赖软键盘回车，不可发现。
  - 重构为共享组件 `ModelAddControl`：受控输入框 + 显式"添加"按钮，回车和点击按钮都走同一个 `commit()`，提交的是真实输入值；`addModelRow()` 改为 `addModel(model: string)`。编辑面板与新建弹窗统一复用该控件，两处行为一致。
  - 移动端友好：输入框高度提升到 `h-9`，添加/同步按钮 `size="sm"`，`enterKeyHint="done"` 让软键盘回车键显示为"完成"。

### 变更

- **渠道连通性测试迁移到 Rust**：原测试逻辑在 TS `provider-admin.ts` 的 `testProviderConnectivity` 里直连上游（用渠道自己的 `targetBaseUrl` + 真实凭证），不经过 Rust；TS 接口将逐步废弃。改为：
  - Rust 新增端点 `POST /admin/providers/{channel}/test`（新模块 `rust-proxy/src/provider_test.rs`）：从已同步的 `RoutingTable.providers` 取渠道配置（`targetBaseUrl` / `auth` / `type` / `models`），用 `state.http_client` 直连上游探测（沿用「Reply with exactly OK」+ `max_tokens 1024`、30s 超时、Anthropic 补 `/v1`、错误码友好提示、思考模型判定等全部旧规则），返回与旧实现同构的 `{ status, statusCode, message, latencyMs, model, rawResponse }`。端点用 `GATEWAY_API_KEY`（x-api-key / Bearer）做管理鉴权，未同步配置返回 503。
  - TS `testProviderConnectivity` 改为本机转发（`http://127.0.0.1:{RUST_PROXY_PORT}/admin/.../test`，带 `x-api-key: GATEWAY_API_KEY`），返回 `{ status, body }` 结构不变 → `/__console`（cookie 鉴权）与 `/api/v1`（Bearer 鉴权）两个入口、前端 `TestProviderResult` 均无需改动。
  - 验证：重启 Rust 进程后，对 anthropic(openai) 类型渠道分别命中成功（`status:ok` + usage token）、401/429 错误（友好提示与旧实现一致）、渠道不存在（404）等分支，直连 Rust 与经控制台路由（TS→Rust→上游）两条路径结果一致。

- **移动端隐藏顶部导航的「全宽」切换按钮**：该按钮控制的是内容区 `max-w-[1540px]` 居中约束，移动端屏幕远窄于该宽度，约束本就不生效，按钮纯属冗余。在 `nav-bar.tsx` 给该按钮加 `max-md:hidden`（与同导航里 Cpu/API/Settings 按钮的隐藏断点一致），仅移动端隐藏；PC 端按钮与 `layout-full-width` localStorage 持久化逻辑不变，刷新/重开浏览器状态照常恢复。
  - 表单改为 `header(shrink-0) / 滚动 body(flex-1 overflow-y-auto) / 粘性保存 footer(shrink-0)` 三段式，保存按钮在移动端底部抽屉里始终可见，无需滚到最底部；同步调整移动端 `Sheet` 包裹层为 `min-h-0 flex-1`、桌面面板去掉冗余 `overflow-auto`，让表单内部滚动接管。
  - 标题栏（编辑渠道 + 渠道名 + 启用开关 + 删除）改为 `flex-wrap`，启用/删除按钮分组到 `ml-auto` 容器，渠道名加 `min-w-0 truncate`，窄屏下不再横向溢出；内边距改为响应式 `px-5 py-3 sm:px-6 sm:py-4`。
- **渠道列表顶部工具栏/筛选栏移动端适配**：渠道数 + 测试全部/导出/导入/新增按钮行、搜索框 + 类型/状态筛选行均改为 `flex-wrap`，搜索框加 `basis-[10rem]`，窄屏下自动换行而非挤压。
- **触控目标放大**：模型 chip 的移除按钮（`-mr-1 p-1`）、凭据显示/隐藏眼睛按钮（`p-1.5`）、删除按钮（`p-1`）加大点击区域，便于移动端点按。
- **新建渠道弹窗**内边距响应式（`px-5 sm:px-7`），小屏下减少左右留白。
- **i18n**：新增 `providers.modelInputPlaceholder`（中/英），给模型输入框一个明确的占位提示。
